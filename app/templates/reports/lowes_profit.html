利润率专项 · 诊断与行动方案

Lowes 利润率为什么保不住 10%，以及怎么保住它

把"利润率≥10%"从事后才发现的结果，变成事前定死、事中可控的目标。核心结论：定价不是主要问题，退货的两半损失（货值 + 运费）没算全、也没收回才是。

01

诊断：问题到底出在哪

按 90 天考核口径拆解，三个运营的净利率是"好毛利被退货吃穿"，不是价定低了。

读法：真实毛利率 − 待追敞口全损率 − 确认退损率 ≈ 修正净利率。例：明瑞瑞 13.9% − 4.9% − 0.1% = 8.9%。"待追敞口"就是这批还没定案的退货，被系统按回收率=0 全额预扣。

根因 1 · 高危退货货值按 100% 全损，因为回收率=0

系统对 Lowes×豪雅退货的回收率写死为 0（全损）——依据是实测：豪雅对 Lowes 退货实际退款 $0，78 笔已登记追款里 77 笔"没动静"（连回应都没有）。于是每笔退货整成本全扣，约吃掉 4.5–5.7 个点净利。

对照：同样是豪雅供货，Macy 那边实测回收率 94.2%。没有道理 Lowes 一分都要不回——这是"没去做"，不是"做不到"。

根因 2 · 高危退货运费严重漏算——你提醒的另一半

损失从来不只是货值，还有把货运回来的退货运费。系统现在的处理几乎等于没算：

退货类型模型假设运费真实情况
无跟踪号（买家退实体店）= 0确实不掏运费，OK
有跟踪号（FedEx 寄回仓）= 售价 × 10%（估）FedEx 实际扣费，常常远超

根因 3 · 中五/六月单是老定价卖的，没预留退货

v5 分档定价 7 月才上线（Autool 07-16、Yasonic 07-22）。之前的单毛利只有名义值、没把退货损失做进价格，退货一到齐净利就掉到 5–9%。v5 已经把退货损失做进目标价，但只对新单生效，要等订单周转。

根因 4 · 中个别"毒 SKU"集中拖累

ATCO-MRLW746900（明瑞瑞）一个月退 4 笔、亏 $2,220，单这一个就压低她当月净利率 1.7 个点。这种连续退货、货又不回仓的品，定价救不了，只能下架。

连带 · Yasonic司顺更狠：退货零回收 + 退店销毁

Lowes-Yasonic（司顺/Vevor）退货退实体店直接销毁，货拿不回、也没跟踪号回仓，回收恒为 0——比 Autool 更没退路。六月朱以超退损率 10.8%，净利率 4.6%，是最危险的 cell。

02

完整的退货损失模型

要保利润率，先得把损失算全。真实的退货损失是两半相加，系统现在只认了第一半的一部分。

退货总损失 = 货值 × (1 − 回收率) + 真实退货运费 ① 货值半边：靠"回收"缩小（追豪雅退款 / 货回仓二次卖）。现状回收=0，全损。 ② 运费半边：纯支出，回收救不了。现状按 0 / 售价×10% 估，实际远超。

定价要盖住的，是这整个损失除以销售额得到的"完整退货损失率"，再加 10% 基线：

定价目标毛利 = 10% 基线 + 货值全损率 × (1 − 回收率) + 真实运费率
现在的口径缺了什么：① 回收率写死 0（最保守，但意味着必须靠定价全额留够）；② 运费只按"售价×10%"估，把 $3,044 这种抛重爆炸和 $535 这种黑洞全漏掉了。两个洞不补，定出来的价永远盖不住真实损失，净利率就永远差那几个点。

03

方案：怎么把 10% 保回来

按损失模型的两半 + 定价 + 闭环四条线动手。每条标了优先级（P1 快且省钱 / P2 结构性 / P3 兜底）。原则不变：保利润率优先，销量可让。

A · 货值半边 —— 把回收从 0 做起来（不牺牲销量）

P1 A1 追豪雅退款：0 → 温和目标 ~20% ▸

关键算过的账：按现在的价，要到 10%，各运营只需要很小的回收率——

运营当前净利达10%只需回收
刘梦蝶9.8%~4%（几乎已到）
明瑞瑞8.9%~23%
朱以超9.1%~20%

Macy 同样豪雅供货能做到 94%。Lowes 只要做到 ~20%（Macy 的零头），明/朱 就达标，一分价都不用涨、销量不掉。

动作：财务对那 78 笔已登记的退货逐笔跟豪雅追款并回填「供应商退款」字段。回收率一从 0 起来，所有月份净利自动上修——这是全盘 ROI 最高、且不掉量的一件事。

P2 A2 货回仓务必二次卖，别写死账 ▸

有跟踪号退回海外仓的货是能二次卖的（成本可全额收回）。要确保这批货真的重新上架/清货，而不是躺仓库当损失。这部分回收是"货在手里"的确定性回收，比追豪雅更稳。

B · 运费半边 —— 独立的一半，回收救不了它

P1 B1 修过度包装 + 申诉 FedEx 抛重错误 ▸

那把伞 $3,044 = 45 寸的伞被门店/仓塞进 60×60 的巨箱，被按抛重 518 磅计费。这类离谱运费可以：①向 FedEx 申诉计费错误；②给仓库定包装规范（按货真实尺寸装箱）。单这一项就能省几千刀，且立竿见影。

建立"运费＞货值"自动预警：一旦某票退货运费超过货值，立刻人工看是不是抛重/包装问题。

P2 B2 把真实运费喂进定价，别再用"售价×10%"估 ▸

定价/恒温器现在用"售价×10%"估退货运费，严重低估。改用 /lowes-return-audit 稽核出的 FedEx 真实运费算各 SKU/类目的运费率，定价才真盖得住。大件（伞、桌）的运费率会明显偏高，定价会自动给它们留更厚毛利。

P3 B3 又贵运费又高退货的大件 SKU 下架 ▸

退一次运费就吃掉整单利润的大件（尤其抛重高的伞类、大桌），如果退货率也高，定价再厚也保不住——直接下架止损，不纠结。

C · 定价半边 —— 目标毛利盖住"完整损失"，用温和而非极端的回收假设

P2 C1 目标毛利 = 10% + 货值损失率×(1−温和回收) + 真实运费率 ▸

不按"回收=0"极端定价（那会过度提价、掉太多量），也不按 Macy 90% 乐观。取一个温和的回收假设（如 ~20%，你能承诺去追的水平），价只盖住剩下的 80% 货值损失 + 真实运费。

这样提价面最小、销量牺牲最少；剩下靠 A（追回收）和 B（控运费）补齐。

P3 C2 盖不住的档位上调，顶档也盖不住的下架 ▸

对完整损失率高的 cell/SKU，把目标档整体上调（明/朱各约 +1 点毛利）。若连顶档（18%名义≈22%毛利）都盖不住（完整损失率＞12%），走下架。这条判据已经写进恒温器。

诚实的代价：C 这条一定会掉一点销量（价定高了）。但按最高原则，利润率优先于销量——而且大部分缺口靠 A（追回收，不掉量）和 B（控运费，不掉量）能补，真需要靠 C 提价的面会很小。

D · 闭环 —— 恒温器盯着真实净利，不达标自动报警

P1 D1 恒温器周体检（已上线，需把真实运费接进去） ▸

每周测各 cell 成熟净利率 vs 10%，判"提价能救 / 退货率过高得下架"，谁贴近红线自动亮。下一步把 B2 的真实运费接进恒温器的损失口径，让它测的是"货值+运费"的完整净利，而不是漏了运费的乐观数。这样它一报"达标"就是真达标。

04

每个环节怎么连成一个闭环

你说的"每个环节之间都有连接"就是这条回路：定价设目标 → 退货产生损失 → 回收与运费控制缩小损失 → 恒温器量真实净利 → 反馈回定价/下架。转起来，利润率才可控。

🎯
定价
目标毛利=10%+完整损失率，把退货预留进价
↩︎
退货损失
货值×(1−回收) + 真实运费，两半
💰
回收+控运费
追豪雅/货回仓 + 修包装/申诉，缩小损失
🌡️
恒温器
周测真实净利 vs 10%，谁不达标亮红
🔁
反馈
不达标→提价/下架/加大追款，回到起点

— 每一环的数据都喂给下一环；恒温器把结果反馈回定价，形成负反馈锁定 10% —

为什么这样才有"确定性"：单靠定价是开环（估一次、听天由命）；靠回收是赌（豪雅退不退不由你）。闭环的意义是——恒温器对着"真实结果"调，不管回收多少、运费多少，只要真实净利＜10% 就自动指出该动谁。回收的不确定性被闭环消化掉了。

先做什么：优先级与预期

顺序动作掉销量?预期
1B1 修过度包装 + 申诉 FedEx不掉立省几千刀，砍掉 $3,044 这类黑洞
2A1 追豪雅回收 0→~20%不掉明/朱 直接达标，刘早已达标
3B2 真实运费进定价/恒温器不掉定价和考核第一次算全损失，不再自欺
4B3+C2 毒SKU/大件下架小掉去掉救不回的亏损品，抬地板
5C1 温和回收假设定价 + 待改价执行会掉剩余缺口靠提价补，面已被 1-4 压到最小

关键判断：前 3 件（省运费、追回收、算全损失）都不掉销量，就能把明/朱 从 9% 拉到 10% 以上。真正需要"提价换利润率"的（第 5 件），面已经被压到很小。所以"保 10%"不必以大幅牺牲销量为代价——牺牲是兜底手段，不是主力。
